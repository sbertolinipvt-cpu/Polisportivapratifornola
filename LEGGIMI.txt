1) MANCA "databaseURL" NELLA CONFIGURAZIONE
   La configurazione che ci hai mandato non include "databaseURL", un
   campo obbligatorio per collegarsi al Realtime Database (senza,
   l'SDK non sa proprio a quale database connettersi). Non è un dato
   segreto. Per trovarlo:
     Console Firebase → Realtime Database → in cima alla pagina trovi
     un URL del tipo:
       https://polisportiva-prati-fornola-default-rtdb.europe-west1.firebasedatabase.app
     (oppure, per i database creati nella regione storica:
       https://polisportiva-prati-fornola-default-rtdb.firebaseio.com )

   Aprite il file js/firebase-init.js, cercate la riga:
       databaseURL: "INSERISCI_QUI_IL_TUO_DATABASE_URL",
   e sostituite il segnaposto con l'URL vero. Finché non lo fate, il
   sito mostra una barra rossa di avviso in alto e il pannello admin
   resta disattivato (il resto del sito, in sola lettura, funziona lo
   stesso mostrando i contenuti di partenza).

2) LE REGOLE "if true" SONO PERICOLOSE — DA CAMBIARE SUBITO
   Ci avete detto di aver impostato le regole di lettura E SCRITTURA
   di Database e Storage su "if true". Questo significa, letteralmente,
   che CHIUNQUE su internet — non solo chi accede dal pannello admin
   del sito — può leggere, scrivere, modificare o CANCELLARE tutti i
   vostri dati e caricare qualsiasi file nel vostro Storage, senza
   nessuna autenticazione. Il login "utente/password" del pannello è
   solo un controllo lato sito: chi conosce un minimo di programmazione
   può bypassarlo del tutto e scrivere direttamente nel vostro database,
   perché le regole lo permettono a chiunque. Essendo voi sul piano
   Blaze (a consumo), questo è anche un rischio economico concreto:
   basta che qualcuno carichi molti file di grandi dimensioni nel
   vostro Storage per farvi salire i costi.

   Per questo motivo, in questa versione il pannello NON usa più la
   coppia utente/password inventata (polis/vezzano) ma un vero login
   con Firebase Authentication (email + password). Dovete fare due cose
   nella Console Firebase:

   a) Authentication → Sign-in method → abilitate il provider
      "Email/Password".
   b) Authentication → Users → "Add user": create un utente con
      un'email e una password a vostra scelta (quella userete per
      accedere al pannello sul sito, al posto di "polis"/"vezzano").

   Poi aggiornate le regole (Database → Regole, e Storage → Regole)
   sostituendo "if true" con una regola che richiede l'accesso:

   Realtime Database → Regole:
   {
     "rules": {
       ".read": true,
       ".write": "auth != null"
     }
   }

   Storage → Regole:
   rules_version = '2';
   service firebase.storage {
     match /b/{bucket}/o {
       match /{allPaths=**} {
         allow read: if true;
         allow write: if request.auth != null
                      && request.resource.size < 15 * 1024 * 1024;
       }
     }
   }

   Con queste regole tutti possono continuare a VEDERE il sito
   normalmente (lettura pubblica), ma solo chi ha fatto login con
   l'utente creato al punto (b) può modificare testi, foto, gare,
   eventi, staff e tabellone.

Come funziona ora (rispetto a prima)
--------------------------------------
Prima, tutte le modifiche dal pannello admin restavano salvate solo nel
browser di chi le faceva. Ora, con Firebase, sono salvate online e
visibili immediatamente a QUALSIASI visitatore, da qualunque
dispositivo — compreso il sito pubblicato su GitHub Pages. Ogni pagina,
quando si apre, si collega al Realtime Database e carica i contenuti
aggiornati; se un amministratore modifica qualcosa mentre altre persone
hanno il sito aperto, quelle persone vedono l'aggiornamento comparire
in tempo reale, senza bisogno di ricaricare la pagina.

NOTA SUI DATI GIÀ INSERITI IN PRECEDENZA: se avevate già provato il
vecchio pannello (quello salvato nel browser), quelle modifiche non
vengono migrate automaticamente su Firebase: dovrete reinserirle una
volta collegato il database, usando lo stesso pannello di sempre.

AREA AMMINISTRATORE (pannello di modifica)
--------------------------------------------
In basso a destra, in ogni pagina, trovate il pulsante "Area riservata".
Accesso con l'email e la password create su Firebase Authentication
(vedi punto 2 in cima a questo file).

Una volta entrati, tutto funziona come prima ma salva su Firebase:
- TESTI: cliccate su un testo (bordo tratteggiato rosso), scrivete,
  uscite dal campo: si salva subito online.
- FOTO: cliccate su qualsiasi immagine modificabile (stemma, sfondo
  dell'header di ogni disciplina, "In evidenza", fotogallery, foto
  staff, locandine di gare/eventi): si apre la scelta file, la foto
  viene caricata su Firebase Storage e il suo link salvato nel
  Database — la vedono subito tutti i visitatori. Sulle foto della
  fotogallery e di "In evidenza" compare anche una "✕" in alto a
  destra per ELIMINARLE (la foto scompare per tutti); per farle
  ricomparire usate il pulsante "Ripristina testi/foto" nella barra
  admin, oppure caricate una nuova foto al loro posto.
- FOTOGALLERY: schede filtro (Tutte le Foto, Allenamenti, Gare & Podi,
  Stage & Eventi) e riquadro "+ Aggiungi foto" in fondo a ogni gallery,
  con didascalia e categoria.
- MAESTRI/ISTRUTTORI (Ju-Jitsu, Pattinaggio, Ginnastica, Pallavolo):
  schede con foto, nome, cognome, profilo; "+ Aggiungi maestro /
  istruttore", "✕" per rimuovere una scheda.
- GARE E RISULTATI (Ju-Jitsu, Pattinaggio, Pallavolo): locandine con
  data/nome/città/palestra; cliccando si apre la finestra con i
  risultati degli atleti (nome, categoria, risultato), modificabile
  da amministratori.
- CALENDARIO EVENTI: "+ Aggiungi evento" sopra ogni calendario (nome,
  data, disciplina, orario, luogo, descrizione, locandina, documenti
  allegati). Cliccando su un evento si apre la scheda completa, con i
  documenti scaricabili.
- TABELLONE ORARI: cliccate su qualsiasi cella (anche vuote) per
  modificarla, "Svuota cella" per liberarla, "✕" per eliminare una
  categoria (anche quelle originali), "+ Aggiungi categoria al
  tabellone" per crearne una nuova.
- Il pulsante "Ripristina testi/foto" in alto riporta i testi e le
  immagini modificabili ai valori originali del sito, per tutti (gare,
  eventi, staff e tabellone non vengono toccati da questo pulsante).
  "Esci" chiude la sessione (Firebase Authentication).

PUBBLICAZIONE SU GITHUB PAGES
--------------------------------
Il sito resta un sito statico puro (HTML/CSS/JS): si pubblica su GitHub
Pages esattamente come prima, caricando tutti questi file nella
repository. Un passaggio in più necessario SOLO per il login:

  Console Firebase → Authentication → Settings → Authorized domains
  → aggiungete il dominio del vostro sito GitHub Pages (es.
  "vostro-utente.github.io"), altrimenti il login dal sito pubblicato
  darà un errore "dominio non autorizzato". "localhost" è già
  autorizzato di default, quindi in locale il login funziona subito.

MAPPA
-----
Mostra la posizione reale della palestra (Arci Uisp - Polisportiva
Prati Fornola, palestra comunale) e cliccandoci sopra apre Google Maps
con la posizione esatta in una nuova scheda.

Note tecniche
-------------
- Limiti dimensione file (lato sito, oltre alle eventuali regole
  Storage): foto fino a 8MB, documenti allegati agli eventi fino a
  12MB. Aumentabili modificando i numeri corrispondenti in js/admin.js
  (cercate "fileTooBig").
- I nomi dei file caricati vengono resi unici automaticamente
  (data/ora + suffisso casuale) per evitare sovrascritture accidentali.
- Sul piano Blaze, l'uso di Database e Storage oltre le soglie gratuite
  è a pagamento: tenete d'occhio la sezione "Utilizzo" della Console
  Firebase, specialmente nei primi tempi.
- Il tabellone degli orari, il calendario e le altre sezioni dinamiche
  restano vuote/di base finché js/firebase-init.js non ha un
  databaseURL valido (vedi punto 1 in cima a questo file).

SE QUALCOSA NON FUNZIONA (es. il pulsante "Area riservata" non compare)
--------------------------------------------------------------------------
Il sito ora è pensato per restare resistente ai problemi: se una singola
parte (gare, staff, tabellone, calendario…) ha un problema di
configurazione, le altre continuano a funzionare e il pulsante di
accesso resta comunque visibile. Se qualcosa non va:

1. Aprite la pagina, premete F12 (o tasto destro → Ispeziona) e andate
   sulla scheda "Console": eventuali errori appaiono in rosso, con
   scritto in quale parte del sito si sono verificati (es. "Errore nel
   modulo 'gare e risultati': ...").
2. Le cause più comuni:
   - databaseURL sbagliato o non ancora inserito (vedi punto 1 in cima).
   - Provider "Email/Password" non abilitato in Authentication → Sign-in
     method.
   - Utente admin non creato in Authentication → Users.
   - Regole di Database o Storage con un errore di sintassi (copiatele
     esattamente come indicato al punto 2 in cima).
   - Se il login non funziona da GitHub Pages ma funziona in locale:
     manca il dominio tra gli "Authorized domains" di Authentication
     (vedi sezione "Pubblicazione su GitHub Pages").
3. Se non riuscite a risolvere, copiate il messaggio di errore esatto
   dalla Console: aiuta moltissimo a capire cosa non va.
